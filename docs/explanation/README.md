# Explanation

Understanding-oriented material: why the tool works the way it does. This
is where design decisions, methodology and architectural reasoning live,
as opposed to step-by-step instructions (`../tutorials/`, `../how-to/`) or
generated technical reference (`../reference/`).

Contents:
- `adr/` — architecture decision records, numbered and dated on the day
  each decision was actually made. Start here as a technical reviewer:
  this is the second thing to open after the README, and the way design
  boundaries are recorded as decisions with reasons instead of a
  known-limitations list.
- `METHODOLOGY.md` — planned consolidated definitions for the metrics exposed
  through the eventual scenario-analysis interface. Not yet available.
- [`VALIDATION.md`](../../VALIDATION.md) — generated by
  `scripts/generate_validation_report.py` from documented numerical cases.
  It distinguishes reference-component comparisons from end-to-end validation.
- `ARCHITECTURE.md` — planned consolidated overview of the modelling engine,
  optimisation layer, API and frontend. Not yet available.
