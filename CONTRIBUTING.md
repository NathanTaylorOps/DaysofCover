# Contributing

Days of Cover is a solo project with a public plan, so contributions are welcome but the scope is fixed per release. Before writing code, open an issue describing the change and wait for a reply; a pull request that lands outside the current milestone will be closed with thanks.

## Setup

```
git clone https://github.com/NathanTaylorOps/DaysofCover.git
cd daysofcover
uv sync
uv tool install pre-commit
pre-commit install
```

## Before you push

```
uv run ruff check .
uv run ruff format --check .
uv run mypy
uv run pytest
```

The `fast` workflow runs the same four commands on every push. Pull requests must pass it.

## Rules that apply to every change

- One behaviour per commit, with its test and its doc touch in the same commit.
- Every number the tool shows is traceable to the inputs and labelled with the failure that caused it. No number comes from an external feed or a language model.
- Synthetic data only. The example networks are generated by a seeded script; never commit data about a real company.
- The user interface uses practitioner vocabulary; academic names belong in `docs/explanation/METHODOLOGY.md`.
- Design boundaries are recorded as architecture decision records under `docs/explanation/adr/`, each with its reason.
